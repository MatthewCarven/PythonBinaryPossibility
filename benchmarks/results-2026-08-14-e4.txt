E4 — the generator as predictor. The admission bar, from ideas.md:
a generator earns a packet type only if it lowers the residual against
the predictor already there. The claimed class: enumerations.

------------------------------------------------------------------------------
 0. THE IDENTITY AT CORPUS SCALE — the packet's price is a theorem
------------------------------------------------------------------------------
  log2(A!) closed form            954,036.9 bits   ceiling 1.0991x
  charge(enum/shuffled)           954,036.9 bits   delta +7.9e-09
  charge(enum/ordered)            954,036.9 bits   identical: order-blind
  escape overhead when clean          16.00 bits   (= log2(A+1) = 16.00)

  A full-alphabet permutation IS one round of the bag, so its charge is
  log2(A!) exactly, for ANY order of the values — the coder is the
  process, now at corpus scale rather than in a unit test.

 2. THE NEAR-PERMUTATION — 2% substituted, one round (N = A)
------------------------------------------------------------------------------
  Real enumeration-shaped data will not be a perfect permutation. At
  byte width, E3 said imperfection demands a window. Here N = A — the
  file IS one round — and the story inverts:

  model on 2%-substituted shuffled enum           ratio   miss
  order=1, window=0  (running counts)           1.0792x   2.0%
  order=1, window=256                           1.0001x      —
  order=1, window=4096                          1.0023x      —
  order=2, window=0                             1.0005x      —

  Running counts keep 80% of the available saving at 2% — almost
  exactly E3's 82% — and every window DESTROYS the structure instead of
  protecting it. No contradiction with E3: E3's laggard trap needs the
  minimum count to advance, and in a single round it never does. The
  window's job is to separate rounds; one round needs none.

 3. THE ROUND IS THE WINDOW — width 12, four rounds (N = 4A)
------------------------------------------------------------------------------
  clean 4-round bag output, window=0      1.1365x   exact vs 4*log2(A!): True
  clean 4-round bag output, window=4096   1.1365x   exact vs 4*log2(A!): True

  2%-substituted, seeds 3/4/5              ratio (median of 3)
  window=0  (running counts — E3's v1)                 0.9677x
  window=A/2 (2048)                                    1.0316x
  window=A   (4096)  — ONE ROUND                       1.1088x
  window=2A  (8192)                                    0.9782x
  order=2, window=0 (softening, not the fix)             0.9845x
  word order-0 (blind control)                         0.9751x

  Multi-round imperfect data replays E3's collapse exactly — running
  counts fall BELOW 1.0 once the minimum starts advancing — and the fix
  is not 'a window' but a specific one: ONE ALPHABET'S WORTH. Half a
  round forfeits the exhaustion; two rounds re-admit the trap inside
  each window. Which reprices E3's own result: its winning window=256
  at width 8 was never an arbitrary grid point. 256 WAS the alphabet.
  One rule covers both experiments: the model lives at round scale,
  window = A per round of data, 0 when the file is a single round.

 4. THE ROW THAT REFUSED TO LOSE — balance pointed at residuals
------------------------------------------------------------------------------
  Ordered-enum residuals after predict-and-cancel: constant 2s with one
  spike at the sign wraparound — width 17, as peaked as data gets.
  Balance should have no business here. And yet:

    balance packet          13.1x   at a 100.0% miss rate
    word order-0             6.2x   (Laplace prior 2^17 — over-smoothed)
    lzma on the bytes      756.9x   the actual incumbent

  DO NOT BANK THE 13x. At a 100% miss rate the model never once used its
  eligible set: every symbol went through the escape, whose miss cost
  log2(A - |eligible|) is ~0 bits when exactly one value is over quota.
  The escape has degenerated into a repeat-the-hot-value coder — the
  E3 audio footnote's hot/cold split, reproduced on demand — and the
  fair frequency baseline it embarrasses is over-smoothed at this width.
  Against the real incumbent it is 58x short. Rule, restated from E3 and
  now with a clean example: a balance CODER can post a ratio while the
  balance MODEL is dead. Quote the miss rate or quote nothing. The aged
  local frequency baseline stays the open item that settles audio.

 VERDICT
------------------------------------------------------------------------------
  The plan predicted E4 would be the best case measured all project.
  It is — precisely bounded:

  * ADMITTED, for the enumeration class. On a shuffled full-alphabet
    permutation the packet reads 1.0991x where every incumbent —
    gzip, lzma, bz2, rice, register, bit-tree — reads 0.93–1.00x. It is
    the first corpus item where the balance model beats ALL incumbents,
    it does so at the theoretical ceiling exactly, and the win survives
    2% dirt at 80% strength. Structured near-permutation data (dealt
    records, round-robin logs, id sweeps) is the packet's home ground.
  * The window law unifies: window = one round (A symbols), 0 for
    single-round files. E3's 256 was the alphabet all along.
  * NOT a residual describer. The 13x in §4 is the escape degenerating
    into a frequency split at 100% miss — a warning shot for the audio
    row, not a result. The narrow §7 claim of the plan stands verbatim.

  Kill criteria, assessed:
  * 'Balance model fails to lower the residual on the enumeration
    class' — NOT triggered: lowered by ~9% where nothing else moves.
  * 'An incumbent already captures it' — NOT triggered: best incumbent
    on enum/shuffled is 1.0007x (bz2, noise).
  * 'Only wins on its own output' — NOT triggered: enum/shuffled is a
    corpus item that predates the generator by two design threads.
